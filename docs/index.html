Deploy Roblox like infrastructure

Predictable, reviewable, and CI-friendly. Built on years of real Roblox deployment experience.

Plan first
Field-level diffs

Every deploy starts with a plan: per-field +, -, and ~ markers, explicit destructive warnings, and the option to bail before a single byte hits Roblox.

See a plan →

Drift-aware
Reconciles with reality

Verifies persisted state against the live Roblox API and re-creates anything someone deleted in the dashboard.

CI native
Built for pipelines

Detects piped contexts, supports remote state in S3 / R2, and ships a single static binary. Drop it in a workflow and forget it.

Resources
Places, badges, products & more

Experiences, places, developer products, game passes, badges, asset aliases, social links, notifications, spatial voice, thumbnails — all as YAML.

Schema-aware
Editor autocomplete

A JSON Schema is generated from source, so your editor knows every valid field, value, and shape inside lithos.yml.

Declarative
Describe the shape, not the steps

Lithos figures out what to create, update, and delete to match the YAML you wrote.

target:
  experience:
    configuration:
      genre: building
    places:
      start:
        file: game.rbxlx
        configuration:
          name: Getting Started with Lithos
Continuous deployment
One job, one binary

Drop a workflow, point it at a state bucket, and let Lithos handle the rest.

- name: Deploy
  run: lithos deploy
  env:
    ROBLOSECURITY: ${{ secrets.ROBLOSECURITY }}
    AWS_ACCESS_KEY_ID: ${{ secrets.AWS_KEY }}
    AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET }}
