Configuration

Config file resolution

All Lithos commands accept a PROJECT argument which tells Lithos where to look for your config file. Lithos uses the following rules to find your config file:

  1. If the PROJECT argument was not provided, Lithos treats the current directory as the project directory.
  2. If the PROJECT argument was a directory, Lithos checks that directory for lithos.yml, then lithos.yaml, then lithos.json, then legacy mantle.yml, then mantle.yaml.
  3. If the PROJECT argument was a file, Lithos uses it directly. Explicit config paths can point to either YAML or JSON files.

If multiple discovered config files are present, Lithos uses the same order: lithos.yml, then lithos.yaml, then lithos.json, then legacy mantle.yml, then mantle.yaml. If no config file is found, Lithos exits with an error that lists those search paths in order.

Lithos prefers the Lithos-named files when both Lithos and Mantle variants are present, which lets you keep a legacy file around during migration while silencing warnings once lithos.yml, lithos.yaml, or lithos.json exists.

File path resolution

Many Lithos config properties require file paths or globs. All file paths should be written relative to the config file's directory.

For example, with the directory structure:

    • lithos.yml
    • game.rbxl
      • game-icon.png
      • thumbnail-1.png
      • thumbnail-2.png

    • You would use the config:

    project/lithos.yml
    target:
  experience:
    configuration:
      icon: marketing/game-icon.png
      thumbnails:
        - marketing/thumbnail-1.png
        - marketing/thumbnail-2.png
    places:
      start:
        file: game.rbxl

    Lithos will correctly find the referenced files no matter where you execute Lithos from.

    The same project-root resolution also applies to .env files: Lithos loads the .env next to the resolved config file in addition to any .env in the current working directory.

    Outputs command defaults

    lithos outputs can be configured from the project file instead of requiring the full output target on every command line.

    Add a top-level outputs block:

    project/lithos.yml
    outputs:
  writeDir: src/shared/generated
  outputName: lithosOutputs
  format: luau
  robloxTs: true

    Or, for easier migration from tools like Asphalt, use the alias codegen plus snake_case field names:

    project/lithos.yml
    codegen:
  write_dir: src/shared/generated
  output_name: lithosOutputs
  format: luau
  typescript: true

    Supported properties:

    • path: full output file path.
    • writeDir + outputName: build the path from a project-relative directory and file name.
    • format: json, yaml, yml, lua, or luau.
    • robloxTs: write a .d.ts sidecar when the resolved output is Luau.

    Rules to know:

    • Use either path or writeDir + outputName, not both.
    • If outputName has no extension, Lithos adds one from format.
    • If robloxTs / typescript is enabled and no format is set, Lithos defaults to .luau.
    • CLI flags such as --output, --format, and --roblox-ts override config values.

    YAML and JSON syntax

    Lithos config files can be written in either YAML or JSON. Directory auto-discovery looks for lithos.yml , lithos.yaml, and lithos.json; the legacy fallback remains mantle.ymlandmantle.yaml`. Config examples in this guide can be switched between YAML and JSON, and the same schema and field names apply to both.

    JSONC and comments are not supported.

    To quickly get started with YAML syntax, see "Learn YAML in Y Minutes (opens in a new tab)" or read through the examples in this guide and in the Examples (opens in a new tab) repo.

    Schemas

    You can view the JSON schemas for the config files below (only for versions above 0.11.0). You can also use the schema to add autocomplete and validation while editing either YAML or JSON config files. For VS Code, install the YAML (opens in a new tab) extension for YAML files and use the built-in JSON language support for JSON files, then add the following to your settings:

    VS Code YAML files

    "yaml.schemas": {
  "https://siriuslatte.github.io/lithos/schemas/v0.3.0/schema.json": ["lithos.yml", "mantle.yml"]
}

    VS Code JSON files

    "json.schemas": [
  {
    "fileMatch": ["lithos.json"],
    "url": "https://siriuslatte.github.io/lithos/schemas/v0.3.0/schema.json"
  }
]
