# Getting started

Install Lithos, wire up credentials, deploy the sample project, change
it, and roll it back — all in under ten minutes.

<Callout type="info">
  By the end you will have the `lithos` binary on your `PATH`, a working
  Roblox Open Cloud key and `ROBLOSECURITY` cookie, and a deployed `dev`
  environment created from the
  [getting-started example](https://github.com/siriuslatte/lithos/tree/main/examples/projects/getting-started).
</Callout>

## Prerequisites

| Requirement | Notes |
| --- | --- |
| **Git** | [Install it](https://git-scm.com/downloads) if you do not have it. |
| **A UTF-8 terminal** | PowerShell, Windows Terminal, macOS Terminal, or any modern Linux terminal. Legacy `cmd.exe` will garble Lithos' box-drawing output. |
| **A Roblox account** | Lithos can only deploy to experiences your account owns. |

## 1. Install Lithos

[Foreman](https://github.com/Roblox/foreman) is the recommended path. It
pins the Lithos version per repo and keeps local and CI machines aligned.

<Tabs items={["Windows", "macOS / Linux"]}>
  <Tab>
    1. Download `foreman-x.x.x-win64.zip` from the
       [Foreman releases](https://github.com/roblox/foreman/releases) page and
       extract `foreman.exe` somewhere stable (e.g. `C:\Programs\foreman\`).
    2. Add that folder *and* `%USERPROFILE%\.foreman\bin` to your `PATH`.
    3. Verify in a new PowerShell window:
       ```ps1
       foreman --version
       ```
  </Tab>
  <Tab>
    1. Download `foreman-x.x.x-macos.zip` (or `-linux.zip`) from
       [Foreman releases](https://github.com/roblox/foreman/releases) and move
       the binary onto your `PATH` (e.g. `/usr/local/bin/`).
    2. Add `~/.foreman/bin` to your `PATH` in your shell rc.
    3. Verify:
       ```bash
       foreman --version
       ```
  </Tab>
</Tabs>

Then clone the example repo and let Foreman install Lithos:

```bash
git clone https://github.com/siriuslatte/lithos
cd lithos/examples
foreman install
lithos --version
```

Foreman reads the pinned version from `examples/foreman.toml`.

<Callout type="info">
  Prefer a direct binary? See
  [Installation → Manually download from releases](/docs/installation#manually-download-from-releases-simplest).
</Callout>

## 2. Authenticate

Lithos needs two credentials for almost every deploy:

| Variable | Purpose |
| --- | --- |
| `ROBLOSECURITY` | Legacy Roblox APIs (place uploads, configurations, social links). |
| `LITHOS_OPEN_CLOUD_API_KEY` | Open Cloud (asset uploads, place publishing). |

1. Create an Open Cloud API key in the
   [Creator Hub](https://create.roblox.com/dashboard/credentials) with
   `universe-places:write`, `asset:read`, and `asset:write` scoped to the
   experiences you will manage.
2. If Roblox Studio is signed in on this machine, Lithos can usually read
   `ROBLOSECURITY` from the OS keychain automatically.
3. Put both in a project-root `.env` and add `.env` to `.gitignore`.

```shell filename=".env"
LITHOS_OPEN_CLOUD_API_KEY="…"
ROBLOSECURITY="…"
```

<Callout type="warning">
  Never commit `.env`. `ROBLOSECURITY` is the equivalent of your Roblox
  password. See [Authentication](/docs/authentication) for full details.
</Callout>

## 3. Deploy

From `examples/`:

```text
$ lithos deploy projects/getting-started --environment dev
```

A deploy shows which config and state file Lithos loaded, the plan it
intends to apply, and the resulting Roblox URLs.

```text filename="lithos deploy"
Loading project:
  ╷
  │  Loaded config file projects/getting-started/lithos.yml
  │  Selected provided environment configuration dev
  │  No previous state for environment dev
  │
  ╰─ Succeeded
```

On a first deploy, the plan is all creates:

```text filename="lithos deploy"
Deploying resources:
  ╷
  │  + Creating: experience_singleton
  │  + Creating: place_start
  │  + Creating: placeFile_start
  │  …
  │
  ╰─ Succeeded with 6 create(s), 0 update(s), 0 delete(s), 0 noop(s), 0 skip(s)
```

That summary line is usually the fastest signal in CI logs.

```text filename="lithos deploy"
Target results:
  ╷
  │  Experience: https://www.roblox.com/games/8667346609
  │  Places:
  │    start: https://www.roblox.com/games/8667346609
  ╰──○
```

Open the link to launch the experience.

## 4. Make a change and re-deploy

Edit `projects/getting-started/lithos.yml` and change the place name:

```yaml filename="projects/getting-started/lithos.yml" {9}
target:
  experience:
    configuration:
      genre: building
    places:
      start:
        file: game.rbxlx
        configuration:
          name: Going to the moon with Lithos
```

Run deploy again:

```text
$ lithos deploy projects/getting-started --environment dev
```

You should get **one update** and the rest noops:

```text
Succeeded with 0 create(s), 1 update(s), 0 delete(s), 5 noop(s), 0 skip(s)
```

That is the core workflow: change config, rerun deploy, apply only the
minimum diff. Lithos also recorded a checkpoint before the update.

## 5. Undo a bad deploy

```text
$ lithos undo projects/getting-started --environment dev
```

`undo` imports live state, compares it to the last checkpoint, shows the
rollback plan, and applies it.

## 6. (Optional) clean up

```text
$ lithos destroy projects/getting-started --environment dev
```

Roblox does not allow hard-deletes for most asset types, so `destroy`
archives the assets and removes them from Lithos state.
