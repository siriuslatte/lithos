# Configuration

Lithos configs can be YAML or JSON. This page covers file discovery, path
resolution, `outputs` defaults, and schema tooling.

## Config file resolution

All Lithos commands accept a `PROJECT` argument. Lithos resolves it like
this:

1. If `PROJECT` is omitted, Lithos treats the current directory as the
  project directory.
2. If `PROJECT` is a directory, Lithos checks that directory for
  `lithos.yml`, then `lithos.yaml`, then `lithos.json`, then legacy
  `mantle.yml`, then `mantle.yaml`.
3. If `PROJECT` is a file, Lithos uses it directly. Explicit config paths
  can point to YAML or JSON.

If more than one discovered config exists, Lithos uses that same order.
`lithos.*` wins over legacy Mantle names.

## File path resolution

Paths and globs are relative to the config file directory, not the shell
working directory.

For example, with the directory structure:

<FileTree>
  <FileTree.Folder name="project" defaultOpen>
    <FileTree.File name="lithos.yml" />
    <FileTree.File name="game.rbxl" />
    <FileTree.Folder name="marketing" defaultOpen>
      <FileTree.File name="game-icon.png" />
      <FileTree.File name="thumbnail-1.png" />
      <FileTree.File name="thumbnail-2.png" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

You would use the config:

```yaml filename="project/lithos.yml" {4,6-7,10}
target:
  experience:
    configuration:
      icon: marketing/game-icon.png
      thumbnails:
        - marketing/thumbnail-1.png
        - marketing/thumbnail-2.png
    places:
      start:
        file: game.rbxl
```

The same rule applies to `.env`: Lithos loads the file next to the resolved
config, plus any `.env` in the current working directory.

## Outputs command defaults

`lithos outputs` can read defaults from the project file.

Add a top-level `outputs` block:

```yaml filename="project/lithos.yml"
outputs:
  writeDir: src/shared/generated
  outputName: lithosOutputs
  format: luau
  robloxTs: true
```

Or use the alias `codegen` with snake_case names:

```yaml filename="project/lithos.yml"
codegen:
  write_dir: src/shared/generated
  output_name: lithosOutputs
  format: luau
  typescript: true
```

Supported properties:

- `path`: full output file path.
- `writeDir` + `outputName`: build the path from a project-relative directory and file name.
- `format`: `json`, `yaml`, `yml`, `lua`, or `luau`.
- `robloxTs`: write a `.d.ts` sidecar when the resolved output is Luau.

Rules to know:

- Use either `path` or `writeDir` + `outputName`, not both.
- If `outputName` has no extension, Lithos adds one from `format`.
- If `robloxTs` / `typescript` is enabled and no `format` is set, Lithos defaults to `.luau`.
CLI flags such as `--output`, `--format`, and `--roblox-ts` override config
values.

## YAML and JSON syntax

Lithos configs can be written in YAML or JSON. Auto-discovery looks for
`lithos.yml`, `lithos.yaml`, `lithos.json`, then legacy Mantle names. The
same schema and field names apply to both formats.

JSONC and comments are not supported.

If you need a YAML refresher, see
[Learn YAML in Y Minutes](https://learnxinyminutes.com/docs/yaml/) or the
[examples](https://github.com/siriuslatte/lithos/tree/main/examples) repo.
