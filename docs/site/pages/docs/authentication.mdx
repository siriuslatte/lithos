# Authentication

Lithos usually needs `ROBLOSECURITY` and an Open Cloud key. Add S3
credentials only if you use remote state. Keep them in environment
variables or a project `.env` file.

| Credential | Used for | Required for |
| --- | --- | --- |
| `ROBLOSECURITY` | Legacy Roblox APIs (place uploads, configurations, social links, etc.) | Almost every deploy. |
| `LITHOS_OPEN_CLOUD_API_KEY` | Roblox Open Cloud (asset uploads, place publish, etc.) | Most deploys; required for asset uploads. `ROBLOX_OPEN_CLOUD_API_KEY` and `MANTLE_OPEN_CLOUD_API_KEY` are also accepted. |
| `LITHOS_AWS_ACCESS_KEY_ID` / `LITHOS_AWS_SECRET_ACCESS_KEY` / `LITHOS_AWS_INHERIT_IAM_ROLE` | S3 / Cloudflare R2 remote state | Only when using [remote state](/docs/remote-state). |

Lithos still honors the legacy `MANTLE_*` names. See
**[Migrating from Mantle](/docs/guides/migrating-from-mantle)**.

## `ROBLOSECURITY`

This is the same browser cookie Roblox uses for [roblox.com](https://www.roblox.com)
and Roblox Studio. Lithos tries to read it for you first:

- **If Roblox Studio is signed in on this machine**, Lithos can usually read
  the cookie from the OS keychain.
- **If not**, set it explicitly:

  <Tabs items={["Bash / zsh", "PowerShell"]}>
    <Tab>
      ```bash
      export ROBLOSECURITY="…"
      ```
    </Tab>
    <Tab>
      ```ps1
      $env:ROBLOSECURITY = "…"
      ```
    </Tab>
  </Tabs>

  Or add it to a `.env` file at the project root.

<Callout type="warning">
  A `ROBLOSECURITY` cookie is the equivalent of your Roblox password.
  Never commit it. Add `.env` to `.gitignore`, and rotate the cookie if it
  leaks.
</Callout>

### Extracting the cookie manually

If automatic detection does not find the cookie:

1. Sign in to [roblox.com](https://www.roblox.com) in any modern browser.
2. Open DevTools → Application → Cookies → `https://www.roblox.com`.
3. Copy the value of the `.ROBLOSECURITY` cookie.
4. In CI, store it as a secret named `ROBLOSECURITY`.

## `LITHOS_OPEN_CLOUD_API_KEY` (preferred)

Use `LITHOS_OPEN_CLOUD_API_KEY` in new setups. Lithos also accepts
`ROBLOX_OPEN_CLOUD_API_KEY` and `MANTLE_OPEN_CLOUD_API_KEY`.

To create a key:

1. Go to the [Creator Hub credentials page](https://create.roblox.com/dashboard/credentials).
2. Create a new API key.
3. Add the experiences this project deploys to under **Access Permissions**.
4. Grant the operations Lithos needs:
   - `universe-places:write` — for publishing places.
   - `asset:read`, `asset:write` — for uploading image and audio assets.
5. Optionally restrict the key by IP.
6. Set the key.

Example `.env` entry:

```shell filename=".env"
LITHOS_OPEN_CLOUD_API_KEY="…"
```

Deploy preflight checks this key before apply when it can. Missing or
mis-scoped keys fail early.

## AWS credentials (only for remote state)

If you use **[remote state](/docs/remote-state)**, Lithos needs S3-compatible
credentials with read and write access to the state object.

```shell filename=".env"
LITHOS_AWS_ACCESS_KEY_ID="…"
LITHOS_AWS_SECRET_ACCESS_KEY="…"
```

For workloads running with an AWS role, set:

```shell
LITHOS_AWS_INHERIT_IAM_ROLE=1
```

and Lithos will use the ambient role instead of explicit keys.

R2-specific setup is documented on
**[Cloudflare R2 remote state](/docs/remote-state/cloudflare-r2)**.

## Using a `.env` file

Lithos automatically loads `.env` from the project root and from the current
working directory. This is the recommended way to keep secrets locally.

If you invoke Lithos from outside the project, for example
`lithos outputs path/to/project`, it still loads the `.env` next to the
resolved project config in addition to any `.env` in the current working
directory.

```shell filename=".env"
ROBLOSECURITY="…"
LITHOS_OPEN_CLOUD_API_KEY="…"

# Only if using remote state
LITHOS_AWS_ACCESS_KEY_ID="…"
LITHOS_AWS_SECRET_ACCESS_KEY="…"
```

```shell filename=".gitignore"
.env
.env.*
```

Do not commit `.env`. In CI, inject the same values as secrets.
