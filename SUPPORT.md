# Support

Lithos support is offered on a best-effort basis. There is no guaranteed response time, no paid support tier, and no promise of emergency turnaround for production game incidents.

## What maintainers can usually help with

Maintainers are generally willing to look at:

- reproducible Lithos bugs and regressions
- install/build problems in this repository
- docs gaps and confusing workflow guidance
- focused feature requests that map clearly to Lithos behavior
- contribution workflow questions for this repository

## What maintainers usually cannot do

Support is usually not available for:

- private consulting on your game's architecture
- urgent production debugging for your experience or team pipeline
- debugging third-party Roblox tooling that Lithos does not own
- recovering from leaked credentials or other active security incidents in public issue threads

## Usage questions

There is no separate discussion forum or chat support channel published in this repository today.

If you have a usage question:

1. Check the README and the docs site first.
2. Read [CONTRIBUTING.md](CONTRIBUTING.md) if the question is really about working in this repository.
3. If you are still blocked and the question is clearly about Lithos behavior, open a GitHub issue and say that it is a question rather than a bug report.

Include the relevant config snippet, exact command, and the output you are confused by. Questions may be closed after they are answered or if they fall outside the project's scope.

## Bugs and feature requests

- Reproducible bugs belong in GitHub issues.
- Feature requests belong in GitHub issues.
- Pull requests are welcome when the change is already well understood and validated.

For both bugs and PRs, [CONTRIBUTING.md](CONTRIBUTING.md) describes the information maintainers need.

## Security is different

Do not use normal support channels for vulnerabilities or credential-related disclosures.

Follow [SECURITY.md](SECURITY.md) instead.
